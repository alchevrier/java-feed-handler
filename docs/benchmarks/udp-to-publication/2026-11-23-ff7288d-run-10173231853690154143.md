# First paced UDP-to-publication reference baseline

- **Run:** `10173231853690154143`, completed 2026-11-23 16:34:42 UTC.
- **Source:** `ff7288db9abb0f764daadc854f25bcb7dc98bca9` plus the uncommitted
  baseline implementation accompanying this report. No book, mapper,
  arbiter, or ingress tuning changes.
- **Reproduce:** `./gradlew clean build :app:run :app:loopbackBaseline --console=plain --quiet`
- **Host:** Apple M5 Max (18 logical CPUs), macOS 26.5.2 (25F84), ARM64.
  Azul Zulu JDK 26.0.1+8, default JVM settings (G1), no CPU pinning.
- **Topology:** two blocking UDP receiver threads, one arbiter/mapper
  thread, one book writer and one sender. Arbiter and book park for 1 ms
  when idle. Capacities: 64 ingress buffers per leg, 64 reorder slots,
  256 book slots. The arbiter gap timeout is 250 ms.

The `HashMap`/`TreeMap` book receives a synthetic add/partial
execution/delete trace with one active order at a time. Both legs get
each update; which leg sends first alternates. Each workload uses a
fresh run with two seconds of warmup and five seconds measured at
1,024 unique updates/s (2,048 data datagrams/s offered across both
legs). The burst schedule releases 16 updates at each deadline.

The larger bursty tail is more pronounced when measured from the
deadline, which includes the time an update waits behind earlier sends
in the same batch.
This is one instrumented run, not evidence of the dominant cost or a
comparison between book layouts. It does not measure a NIC or a strategy
read. Application drop counters do not observe socket-buffer drops.
